## Cause and correction

The desktop variant configured 3,520 ms before exit and 4,140 ms total duration. The hook scheduled both timers in an effect dependent on `phase`. Entering `exiting` cancelled the pending completion and started a new full-duration timer. That yielded 7,660 ms of scheduled overlay lifetime, plus up to 1,200 ms of font preparation: 8,860 ms excluding bundle download and browser scheduling. The page itself was blocked during preparation/running, not during the entire invisible exit interval.

The corrected lifecycle has one active timer per phase: 800 ms showing the scene, followed by a 240 ms opacity exit. Skip immediately enters `done`, cancelling the timer. There is no font readiness phase, font promise race or font timeout; the editor uses system monospace. Return visits, reduced motion and service routes continue to bypass the intro.

CSS receives its durations from the existing motion module. Row staggering is derived from the actual row count, so the background typing and central statement finish within the shared 600 ms entry period. The long independent row/caret/scanline/promotion timelines were not retained. Activity-bar decoration uses a pseudo-element, and responsive sizing uses `clamp()` without new component-specific breakpoints.

The central statement keeps its intrinsic rendered width. Its small text box is revealed with a stepped clip instead of assuming that `22ch` equals the actual glyph width. Browser checks caught that assumption clipping the closing quote/semicolon because of inherited font metrics. The final string is complete at every checked width.

The existing action primitive provides `Pomiń intro` / `Skip intro`. The button receives initial focus, Tab/Shift+Tab stay on the single intro control, and Escape skips. On release the app loses `inert`, the pending attribute is cleared before focus returns to the first navigation link, and scrolling is unlocked. The fading scene is hidden from assistive technology and its button disabled while the page becomes available.

## Restoration: original wordmark and early startup

The user supplied a screenshot showing the substituted code-editor scene, rejected that redesign, and selected the original large NODE48 wordmark. Their explicit clarification was that letters appeared from above, like printing. The earlier commit/publication authorization did not justify assuming acceptance of a different presentation. The restoration uses the original published Manrope typography, dark background, white NODE and blue 48 from the item 7 baseline, with the entry direction set to the user's clarification. Editor tabs, rows, statement typing and their CSS/timing contracts were removed. The separate dirty desktop checkout remains untouched.

The preceding intro could start only after the application bundle loaded and React hydrated, allowing the page to appear first and the overlay to arrive later. The current presentation is a pure component serialized by the build. A single self-contained native controller is embedded immediately after the body opening, before the prerendered root. The same generator is used by the development server. The build adds the exact script's SHA-256 hash to generated `dist/.htaccess`; it retains the strict script policy without allowing arbitrary inline scripts. There is no additional request or downloaded-font readiness gate.

The native controller owns the only overlay, phase timer, skip/keyboard listeners and background-root access state. React subscribes through `useSyncExternalStore`; it cannot create or restart another intro. Cookie visibility consumes that progress outside the hydrating route boundary. An initial prototype exposed native phase updates to not-yet-hydrated route props; two hydration tests caught replacement of prerendered nodes. Isolating the subscriber corrected it, retaining headings, inputs and pre-hydration drafts.

Six clipped letter slots reveal NODE48 from above. The original 760 ms letter duration and 64 ms stagger produce a 1,080 ms entry. The final letter's actual animation completion begins a 260 ms full-word hold, followed by a 460 ms exit. The 2,080 ms entry timeout reveals the complete word before the same hold/exit if the animation event is missing. Skip and Escape finish immediately; pagehide cancels without recording unseen playback. Each phase has one timer, independent of React. The root remains styled and visible underneath, with temporary `inert`/`aria-hidden` restored on release and no opacity gate on prerendered content.

Session version `wordmark-v1` records entry completion into the full-word hold or explicit skip. Legacy `"1"` and `editor-v2` markers permit the restored version once. Current-version repeat visits, reduced motion and direct non-home entry bypass it. Storage reads/writes are optional and guarded. With the main application script delayed or blocked, the early controller still releases the page; with all JavaScript disabled, the prerendered page is immediately available without an overlay.
